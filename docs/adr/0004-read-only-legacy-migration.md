# 普通打开仅 v2，v1 只作只读迁移输入

用户确认新版本普通 `open` 只接受 v2，有效 v1 报 `UnsupportedFormat`；v1 解码和 shortlex 校验隔离为迁移专用读取功能，不把双排序模式带入普通 writer。显式迁移只读源主文件与 WAL，在内存覆盖有效已提交 redo 后严格按 v1 验证并重建到不同路径，目标主文件和 `.wal` 都须不存在；源文件/WAL 不写、不替换，成功后由调用者显式切换。这用额外空间和重建成本换取清晰的格式切换及源保留；不能复用会回写恢复页、清 WAL 的普通打开路径。[现有打开](../../src/db.mbt#L54-L72)、[覆盖后验证](../../src/storage.mbt#L119-L165)

迁移要求源离线单所有者、目标目录已有且路径稳定，解析已有父目录后源/目标不同；拒绝源主文件/WAL 的叶子符号链接，目标主文件/WAL 不得有任何目录项（含悬空链接），已有源硬链接仍全程只读。必须有有效 v1 头或 WAL 足以恢复完整有效 v1，缺失/零字节无有效头不是空旧库；合法空旧库仍持久写出 v2 头。在目标同目录独占 staging，核对全部键值、条数及图结构，checkpoint/同步主文件并清空同步 staging WAL，再确认最终 WAL 不存在后，以不覆盖 rename 只发布完整主文件，最终 WAL 保持不存在；平台不支持就失败，不降级覆盖。

正常返回才算完成。I/O/取消不改变源，不自动重试、替换或删除最终目标；可能遗留 staging 或已发布完整目标，调用者须检查并人工处理，不能仅凭存在视为成功，只清理本次独占且明确归属的 staging。不增加锁、路径竞态/别名攻击保证或整机掉电承诺，也不宣称跨平台通用原子 rename 或双文件发布。**已实现为仓库 0.4.0 的 `migrate_v1`，随 0.4.1 发布到 Mooncakes。** native 实际运行覆盖真实 v0.3.0 多页/空库、redo 撕裂与 WAL-only 恢复、全部键值字节及图核对、源硬链接保留、目标/源链接拒绝、损坏 WAL 和 staging 期间取消。
